# Validation record

Validated on 2026-10-21, Windows, Node.js v26.3.0 and v24.22.0.

- **Reusable Flutter SDK verified.** `packages/tern_updater` passes 13 controller/widget tests and Flutter analysis. The tests cover selected channels, committed patch readiness, offline staged patches, concurrent checks, dismissal without losing form input, rollback to the original release, restart confirmation, unsaved-work guards, missing native support, and accessible narrow-screen layout.
- **Android SDK restart passed end to end.** On the x86_64 emulator, the example downloaded a real Dart patch, displayed Update ready, and restarted through its banner and confirmation into that code. Revocation repeated the same flow back to the original release. Process IDs changed from 6261 → 6547 → 6728; the original APK hash and Android install timestamp stayed unchanged. No external Force stop was used to apply the patch or rollback. The verifier used a dedicated local server and temporary example, without touching production apps. Evidence: `test-results/flutter-sdk/report.json`, runtime logs, and screenshots. Native restart behavior on physical ARM devices and iOS has not been validated; automatic restart in this package is Android-only.

- **Email/password authentication passed 43 Node tests**, including a run on Node 24.19.0. Private one-use setup, expiry, salted password hashing, recovery, credential persistence after restart, session revocation, concurrent setup protection, origin checks, request throttling, and continued CLI Bearer access are covered.
- **34 browser assertions passed after the authentication update.** Setup from an already-open page, recovery while signed in, email/password login, incorrect credentials, password changes, and all existing release/deploy/rollback/delete flows passed on desktop and mobile without JavaScript or CSP errors. Tests use a disposable database and dummy credentials.

- **Configuration rename passed a real Android build.** The sample migrated to `tern.yaml`, compiled a 19.4 MB x86_64 patch APK, and matched every nonpatchable fingerprint in its existing release. After compilation, the source pubspec referenced `tern.yaml`, and no generated `shorebird.yaml` remained. Evidence: `test-results/config-rename.json`.
- **Linked CLI verified from the Flutter project directory.** `tern --help` executes through npm's global Windows shim, and `tern doctor --server https://43.106.48.165` authenticates using the installation's existing admin key.

- **35 Node tests passed on Node 24.22.0.** Coverage includes authenticated application deletion, exact-name confirmation, dependent-row cleanup, shared artifact preservation, legacy configuration migration, build recovery and failure cleanup, linked CLI execution, current-folder project detection, quoted pubspec versions, multi-megabyte uploads, APK validation, compatibility guards, and cloud entrypoint behavior.
- **Render deployment configuration checked.** The Blueprint passes Render's current official JSON Schema (draft 2020-12, checked locally with Ajv). Entrypoint tests cover HTTPS download URLs, Secure cookies, same-origin login, custom domain precedence, local loopback behavior, and database persistence across process replacement. No cloud service has been created; live hosting still requires account access.
- **VPS configuration checked.** Docker Compose v5.6.1 accepts the standalone VPS file. Its resolved configuration keeps the backend port private, sets the HTTPS public origin, uses persistent volumes, and waits for backend health before starting the proxy. Caddy v2.11.7 validates both the domain and IP proxy configurations. Both local validation binaries were obtained from official releases and checked against their published SHA-256 asset digests.
